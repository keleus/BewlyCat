# BewlyCat PR 工作流

适用于明确的 PR 拉取、审查、本地集成测试或合并请求。遵循根目录 `AGENTS.md`；只读代码审查不要求页面操作或运行开发服务器。

## 模式与执行者

- 从请求和 PR 元数据确定 PR、目标分支与模式：仅审查、本地测试、审查并合并。目标分支默认使用 PR 的 base；仅在缺失信息会影响操作且无法从元数据取得时询问。
- 默认由主 Agent 完成。仅在用户明确指定，或满足根指南的委派条件时使用可调用的 `bewlycat_pr_reviewer`；其可用性和 PR 任务类型本身不触发委派。`.claude/agents/` 中的定义不代表 Codex 当前一定提供该角色。
- 委派给出 PR、base、模式和已授权写入范围。主线程整合 findings 与验证结果；仅在证据缺失、矛盾或提交已变化时补查。

## 审查与本地验证

- 获取 PR 元数据、检查状态与完整 diff，使用目标分支的 merge-base；按实际变更关注正确性、状态/生命周期、Shadow DOM、i18n、浏览器兼容性等相关问题。
- 有用户未提交改动时，可在独立 worktree 中拉取、审查和验证；不覆盖或 stash 用户改动。隔离失败只阻断依赖写入的操作，继续可完成的只读审查。
- 仅审查保留作者源码；不为 review 合入 main。需要集成验证时，在隔离分支按 PR 的实际 base 测试，不硬编码 main。
- 使用根指南中的适用检查；不生产构建、不使用虚拟页面。用户只说“本地测试”仍不授权页面调试或 Chrome DevTools MCP。
- hooks 已覆盖的检查不为提交重复预跑。合并前确认适用的必需检查已通过且对应当前被合并的提交；远程 CI 和本地结果不混称。

## 写入与结束条件

- 仅审查不修改源码、合并、提交或推送。合并、提交、推送分别遵循用户已明确的范围；本地合并不隐含远程推送。
- 在已授权合并范围内，可自主隔离工作区、处理不改变需求语义的常规冲突并复验；涉及产品语义的冲突先报告待定点，继续不受影响的工作。
- 有阻断 findings、未解决冲突或必需验证失败时不合并；不得混入用户修改。
- 审查完成：findings 按严重度排列，问题附文件行号；说明 PR/base/HEAD、验证结果与剩余风险。
- 测试或合并完成：另报最终分支、Git 状态及实际发生的 commit/push。环境阻断或未运行检查如实标明，不能记为通过。
